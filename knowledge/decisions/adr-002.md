# ADR-002: Spec-labelled local Allure report archive

*   **Status**: Superseded by ADR-003
*   **Date**: 2026-09-27
*   **Related Files**: `scripts/run-allure.js`, `scripts/open-latest-allure-report.js`, `.gitignore`

## Context

Timestamp-only archive names do not identify which spec generated a report. Opening the newest report must remain correct when archive names begin with different spec names.

## Decision

For a single spec run, store the report in `allure-history/<spec-name>_YYYY-MM-DD_HH-mm-ss/`. Use `all-specs` for a full-suite run and `multiple-specs` for multiple explicit specs. Select the newest report by modification time.

## Rationale

The directory name identifies the test scope at a glance while retaining sortable run timestamps and a reliable newest-report command.

## Consequences

Archive folders have longer names. Existing timestamp-only folders remain valid and can still be opened.

## Alternatives Considered

* Keep timestamp-only names: rejected because the test scope is not visible.
* Prefix folders but sort names alphabetically: rejected because that may not select the newest report across different specs.

## Review Notes

Verify a login run creates a folder beginning with `login.spec_` and `npm run allure:open` opens the most recently created archive.
