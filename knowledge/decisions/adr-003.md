# ADR-003: Standalone Allure report archives

*   **Status**: Accepted
*   **Date**: 2026-09-27
*   **Related Files**: `scripts/run-allure.js`, `scripts/open-latest-allure-report.js`

## Context

The standard Allure 3 report loads data through HTTP requests and remains blank when its `index.html` is opened through the `file://` protocol. Archived reports must be viewable and shareable without a running local server.

## Decision

Generate each archived report with `allure awesome --single-file`. Each archive retains `results/` and contains one standalone `report/index.html` that opens directly in a browser. `npm run allure:open` launches this file without starting an Allure server.

## Rationale

A self-contained HTML report satisfies offline viewing and straightforward sharing while preserving the existing spec-labelled, timestamped archive structure.

## Consequences

The report HTML file is larger because it embeds report data and attachments. Recipients can view the report by opening the copied HTML file, but cannot use live-server-only features.

## Alternatives Considered

* Serve the standard report with `allure open`: rejected because it requires a running process for each view.
* Share the multi-file report directory: rejected because direct `file://` viewing remains unsupported.

## Review Notes

Verify that opening `report/index.html` directly displays passed and failed test results with no local server.
